# Legacy manual intake resource writer

Manual legacy/shadow close, reopen, pause and resume now revalidate current vendor access after taking the location lock. Unsafe persistence identities reject. The locked branch must still use legacy/shadow mode; current tenant and branch activity, user deletion/suspension state, active membership and `tenant.queue.operate` permission are required. Staff must have a current explicit branch assignment or an assignment to a current active counter at that branch.

Accepted tenant, user, membership and staff assignment/counter rows remain share-locked through commit. Access or mode changes committed while the request waits for the location lock are reread before any state write. The shared actor reader preserves existing vendor transaction behavior; its new share-lock option is used by this manual intake adapter and does not certify locking for every other vendor adapter.

The existing location-first serialization with versioned paid admission remains. Successful intake state, ticket closure/reopen outcomes, events and one scope revision advance commit together. Rejected duplicate/state actions and injected event failures roll back, including a newly inserted scope. Business date is derived after the location lock. Postcommit notifications retain their existing behavior.

This slice preserves legacy closure/reopen policy. It does not add protection cleanup, release actual occupancy, convert reservations, change explicit service timing, certify enforced/system closure or automatic pause/resume revisions, or activate tracking. Those writers remain inventory gaps. Tracking/coverage gates remain off and the producer remains `not_ready`; capture/export/inference and customer estimates are unchanged.

Validation: disposable PostgreSQL full backend suite passed 975 tests with seven opt-in skips (982 total); focused ESLint, backend typecheck and diff checks passed. Coverage was 65.72 percent lines/statements, 68.93 percent branches and 61.15 percent functions; this is not an 80 percent threshold claim. Tests exercise actual ticket SQL and current authorization/assignment locks with minimal transactional closure, pause and event fixtures. They cover all four actions and revisions, close/reopen ticket restoration, revoked access/activity, both staff assignment paths, lock-wait revalidation and event-failure rollback. Full production-schema lifecycle and authenticated live queue operations are not claimed.
