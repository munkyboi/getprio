# Public and customer zero-fee queue issuance

Explicit online/QR, non-developer `queueService.createTicket` calls now enter a location-first customer admission transaction. Server-resolved tenant/location and optional authenticated customer identity are validated before legacy numeric persistence can round them. Current branch activity, slug, timezone and lifecycle mode are reread under the location lock. Tenant activity, current threshold/prefix, customer deletion/suspension state and the accepted subscription retain shared row locks through issuance. The existing queue entitlement gate is rerun on that client, respecting its release controls. Fee lookup uses the accepted subscription plan and retains a shared row lock; a newly enabled positive fee rejects with QUEUE_PAYMENT_REQUIRED so the caller restarts checkout. Unknown mode/fee policy rejects for reconciliation. Missing explicitly requested branch slugs reject rather than choosing a primary branch.

Legacy/shadow admission takes the hours lock before capturing one instant for branch-local date and hours eligibility. Closure, pause, current waiting inventory and threshold are checked on the transaction client. Manual and automatic intake writers use the shared location lock from #345. Enforced admission uses the authoritative Queue Day business date and accepting window. The existing public-route hours preflight remains unchanged. Initial or later overdue checks discard requested issuance and commit existing Queue Day reconciliation/outbox/revision before rejection; reconciliation failures roll everything back. A later retry does not duplicate the closure.

Ticket sequence, ticket record, existing ticket/email allowance admission, email journey/slots, Queue Day segment, queue event/webhook and scope revision commit together. This public issuance entry supplies the callback only a transaction client, with no resource-command capability. Issuance creates waiting work; it never allocates, converts protected bindings or releases existing occupancy. Public tickets without a selected service do not gain an invented executable plan. Notifications, automatic intake adjustment and snapshots remain postcommit.

QR security and OTP verification remain at their existing entry points. OTP verification still commits before issuance; failed admission requires restarting verification. This slice does not add replay/deduplication for separate join requests, fee checkout, developer project authorization, full catalog/override serialization or coverage certification. Historical unversioned paid and developer issuance remain gaps. Missing-channel internal legacy callers also retain their previous adapter. No new API route or response contract is introduced.

## Validation and boundaries

Dedicated PostgreSQL regressions use actual ledger, ticket/sequence persistence, billing/fee eligibility repositories and hours SQL. Allowance, event/webhook and Queue Day lifecycle use bounded transactional fixtures; the queue-feature rejection test injects admission policy while verifying its locked transaction client. Tests cover concurrent QR/customer issuance and final-place contention, current policy/identity changes during lock waits, inactive/wrong scope, suspended subscriptions, newly charged or unknown fee, unknown mode, closure/pause/hours, unsafe IDs, email/allowance/event rollback, authoritative enforced date, overdue checks at three points, retained occupancy, accepted-row locks and no resource-command capability. A service regression rejects missing requested branch lookup. Existing QR/OTP route tests rerun; this is not authenticated live join or full production entitlement/allowance/bootstrap proof.
