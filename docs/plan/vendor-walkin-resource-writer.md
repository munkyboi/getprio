# Vendor walk-in issuance resource writer

Only vendor-channel `queueService.createTicket` admission now uses the shared location-first actor transaction with trusted `tenant.queue.operate` permission. Active user/membership, staff branch or active-counter assignment, active branch/business, lifecycle mode and timezone are reread after acquiring the lock. The Queue Day check keeps committed overdue closure/outbox/revision before rejecting the requested issuance. Public/customer/developer and paid issuance retain their existing paths and remain separate writer gaps.

Vendor admission rereads accepting intake and operating hours using the same transaction client. The hours service accepts optional trusted read options while preserving existing caller behavior. Current database auto-pause settings, waiting inventory and queue prefix supply issuance policy under the location lock. Competing walk-ins, or a walk-in competing with restoration for the same date, cannot both claim the final waiting place. The waiting threshold is distinct from physical resource capacity. Postcommit auto-pause uses the freshly read threshold settings.

The existing persistence helper retains the trusted admission date through sequence allocation and insertion (avoiding a second legacy date calculation across midnight), creates the ticket, consumes ticket/email allowances and creates the email journey/slots on that same client. Selected active branch services are captured with the existing immutable plan/mapping revisions before commit. Ticket, service plan, sequence, allowance writes, event/webhook and scope revision are atomic; errors roll back the requested issuance. A shared action savepoint also handles expiry between the initial open-day check and later intake checks: requested action writes roll back to the savepoint, then current overdue closure/outbox/revision commit before rejection. Failed reconciliation rolls back the transaction. Controlled Queue Day lookup regressions cover expiry on both the second and third read, discarded admission writes, retained actual occupancy and duplicate-safe retries. Notifications, automation and public snapshot remain postcommit. Existing vendor route/response and public non-vendor transaction behavior are preserved.

A walk-in is waiting work, not physical occupancy. Issuing while resources are occupied never allocates, converts protection or releases an existing session. Optional unselected service behavior remains supported; that ticket has no synthesized executable plan, and a tracked location still needs reconciliation before a later unknown-plan start. This does not complete ready eligible-work inventory or activate resource tracking.

Validation uses actual PostgreSQL ticket creation, sequence persistence, service-plan capture and scoped ledger/assignment repositories. Operating-hours reads use the actual repository/service on the transaction client. The production intake check uses a minimal Queue Day lookup fixture; enforced sequence allocation/reconciliation, allowance admission, event/webhook, notification, automation and snapshot behavior use transactional/minimal fixtures. This is not a full production bootstrap, full allowance-policy integration or authenticated live walk-in proof. Regressions cover concurrent sequences, last waiting place including restore contention, frozen plan, unchanged protection/occupancy, optional ordinary service, access and hours changes during lock waits, current enforced mode/business date, inactive or wrong service/branch, email journey and event/webhook/allowance rollback, and committed overdue retry behavior. Existing public creation/push, payment, allowance and service-session regressions rerun.

Final full backend coverage command passed 936 tests/seven unrelated opt-in skips (943 total); focused lint, backend typecheck and diff check passed. Aggregate coverage remains below 80 percent.

Tracking and writer coverage remain disabled, producer remains `not_ready`, and capture/export/inference/customer-estimate contracts are unchanged. Remaining gaps include non-vendor/paid issuance, closure/carry-over expiry, account deletion, catalog/configuration reconciliation and complete ready inventory. No parallel calling or multistage routing is introduced.
