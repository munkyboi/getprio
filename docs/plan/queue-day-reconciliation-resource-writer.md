# Scheduled and Platform Queue Day reconciliation writer

Scheduled closure and explicit Platform reconciliation retries now use a dedicated trusted location-first ledger transaction. The maintenance adapter has no vendor actor and exposes only the transaction client to lifecycle code. Existing Platform route authorization remains the request boundary. Internal maintenance is not chosen from a caller-supplied source or fabricated user identity.

Candidate selection is a nonlocking hint. Unsupported Queue Day/scope identities and inconsistent branch ownership are excluded before the batch limit so old invalid rows cannot starve valid overdue days; unsupported rows remain visible for explicit reconciliation. Before numeric Queue Day repository access, Queue Day and captured tenant/location identities must be safe. After the branch lock, the Queue Day is locked and its captured scope, current state, current enforced mode and database wall-clock deadline are checked again. A stale worker candidate skips; explicit retries reject a current conflict. Closed-day retries retain idempotency. Scope drift or unsafe identities roll back without coerced diagnostic writes.

The branch uses `FOR NO KEY UPDATE` and the tenant uses `FOR KEY SHARE`, permitting branch FK reads in tenant-first grant changes and holding parent identity through closure. Maintenance intentionally permits inactive businesses/branches and revoked vendor memberships to finish overdue cleanup. It does not require or impersonate a vendor actor.

Closure, ticket/booking outcomes, segment effects, warning obsolescence, lifecycle events, durable outbox intents and one branch revision commit together. Competing workers/retries close once. Event/outbox failures roll back operational effects. Scheduled-failure attempt/error/event/notification diagnostics run together in a separate location-first transaction pinned to the captured scope after operational rollback. A moved, removed or already-closed day receives no attempt update, event or notifications. Diagnostic transactions may seed the private scope at revision one but do not advance its operational revision; successful retry advances the operational revision. Transition callbacks remain after commit.

Actual occupancy and explicit service timing are retained; closure does not release allocations or start service. Terminal linked bookings retain their statuses. Terminal unused-protection cleanup is not added.

Real PostgreSQL tests reuse the shared lifecycle/ledger fixture and cover competing worker/retry closure, vendor intake serialization, deadline/mode changes during contention, inactive-business cleanup, held parent locks, tenant-first FK grant changes, event/outbox rollback, separate failure diagnostics and subsequent retry, unsafe/missing identities, scope movement and occupancy/timing retention.

Validation: isolated loopback PostgreSQL full backend coverage passed 1,082 tests with seven opt-in skips (1,089 total), zero failures. Focused source ESLint, backend typecheck and diff checks passed. Coverage: 68.23 percent lines/statements, 69.36 percent branches and 63.85 percent functions; no 80 percent threshold claim.

Standalone request snapshot/intake reconciliation is covered in [request reconciliation](request-reconciliation-resource-writer.md). Existing-client intake reconciliation, other diagnostic/warning ordering, terminal unused-protection cleanup, carry-over activation protection reconciliation, account deletion, related catalog/settings writers and full activation reconciliation remain inventory gaps. Platform grant revocation inside the maintenance transaction is not certified. Tracking and writer coverage remain constrained to false; the producer remains `not_ready`. No UI, migration, customer estimate, capture/export or inference change; authenticated live vendor execution is a separate acceptance gate.
