# Draft resource configuration writer

Resource configuration reads and saves revalidate the authenticated actor under the branch lock. Both `tenant.location.manage` and `tenant.service.manage` must still be granted by a current active membership. Deleted or suspended users, inactive memberships, assigned staff and cross-tenant actors are denied. The route passes the authenticated actor ID; the request body cannot select an actor or scope.

Accepted grants remain locked through commit. Lock order is branch, tenant, then user/membership, matching the staff and Platform membership mutators. Saves use the ledger's location-first boundary with `FOR NO KEY UPDATE`, which serializes branch writers while allowing a tenant-first grant change to perform a branch foreign-key key-share check. Reads retain a coherent branch `FOR SHARE` transaction and create no ledger state. Draft administration does not add an active-tenant or active-branch requirement.

Pool creation/editing and service requirement creation/editing/removal advance the branch ledger revision in the same transaction as configuration. Pool and requirement revisions retain their existing semantics. Removing an absent requirement does not advance the branch revision. Existing configuration hashes reject competing stale saves with 409. Authorization, validation, service availability or post-write failures roll back configuration and scope state together. No ledger reservation, allocation or command is created by these saves.

Verification uses the actual draft and ledger migrations in an isolated loopback PostgreSQL database, including their foreign keys, timestamp triggers and disabled-tracking/coverage checks. Tests cover current access for reads/saves, admin versus assigned staff, scope isolation, accepted grant locks, tenant-first grant changes with a branch foreign-key insert, competing versions, revision rollback and concurrent service deactivation. This is transaction-level evidence; it does not prove authenticated live vendor UI behavior.

Related service catalog, branch/settings mutations and activation reconciliation remain uncovered in the writer inventory. `tracking_enabled` and `writer_coverage_complete` remain constrained to false; the operational producer remains `not_ready`. This slice changes no customer estimates, workflow routing, resource activation or model inference.
