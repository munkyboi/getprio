# Vendor branch settings and reactivation resource writer

Vendor branch PATCH now uses the same catalog service and transaction as POST. Numeric existing-branch locks and the tenant creation boundary precede current held `tenant.location.manage` grants. The branch is reread by server tenant and URL slug using that client; missing, renamed, deleted or foreign branches fail closed. Validation uses current branch payment details, preserves immutable slugs and only changes submitted fields. Active and primary settings require JSON booleans, preventing PostgreSQL boolean coercion from bypassing quota admission.

Inactive-to-active PATCH and active POST share the existing subscription/plan quota reader with held policy rows and NOWAIT contention responses. Their last active seat serializes on the tenant catalog boundary; already active edits and inactive administration do not consume a new seat. The legacy quota merge/default behavior remains unchanged. Branch metadata, primary replacement and one revision for each current branch commit together; revision failure rolls everything back. Repository update, primary lookup and empty-update identifiers retain exact bigint values. Body tenant, actor and branch IDs cannot change the server-selected scope.

Real isolated PostgreSQL tests cover current grants and grant contention, missing/renamed/deleted branches, state changed while waiting, shared creation/reactivation quota, held subscription/plan/grant rows, inactive tenant administration, boolean/timezone/flag/payment validation, current payment details after contention, concurrent partial edits, primary replacement, final revision rollback, exact adjacent large branch identifiers and unchanged admitted bookings, plans, reservations, allocations and hours. Actual route tests cover staff denial, actor forwarding and unchanged ordinary response formatting.

Internal/onboarding branch creation, other settings writers, protection cleanup and activation reconciliation remain follow-up work. Tracking and writer coverage remain disabled; producer stays not_ready. No schema, dashboard/mobile UI, customer estimate, inference, capture or export changes. Authenticated release smoke is separate from live authenticated branch-form execution, which remains unverified.
