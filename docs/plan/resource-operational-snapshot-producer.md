# Internal resource snapshot producer boundary

`createResourceOperationalSnapshotProducer({ pool, sourceBinding, authorize })` returns `readSnapshot({ tenantId, locationId })`. Pool, source binding and authorization come from trusted server configuration, never request-supplied provenance. The authorizer receives the transaction client and frozen v1 scope and must return exactly true. Missing/mismatched locations reject with 404; denied reads reject with 403.

The reader uses one repeatable-read, read-only transaction for location, authorization and scoped ledger/tracking diagnostics. It returns the accepted `resource-operational-snapshot-v1` envelope as a frozen object; consumers serialize it to UTF-8 bytes for the existing validator. Disabled pools or absent configuration return tracking_disabled; absent scope storage returns ledger_unavailable; incomplete coverage returns writer_coverage_incomplete. Missing ledger tables/columns return ledger_unavailable after rollback. Other database failures reject rather than fabricate inventory. A PostgreSQL rollback completion cannot report a successful read.

This implementation always returns not_ready with snapshot null. Even hypothetical tracking/coverage flag changes return inventory_incomplete because complete operational inventory and reconciliation are not implemented. It does not return empty allocations or infer occupancy from Called, timing, forecasts or audits. It has no live caller, public route, model hook, environment import, mutation or tracking activation. No accepted consumer/reference schema changes.

Next producer work requires all booking/session/configuration writers sharing the location-first transaction and monotonic revisions, historical reconciliation, complete cross-date work/actual allocations/protected bindings, stable producer order and freshness/window semantics. The current reader's readiness diagnostics are authoritative for its scoped read; it is not yet an authoritative ready inventory producer.

Tests use the existing explicit disposable RESOURCE_LEDGER_TEST_DATABASE_URL (loopback getprio_ledger_test or CI getprio_test) and create/drop a random fixture schema. They prove accepted v1 validation, authorization/scope denial, immutable null inventory, read-only repeatable-read coherence during concurrent flag changes, incomplete/absent storage fallback and fail-closed hypothetical enabled flags. Both production disabled constraints remain intact.
