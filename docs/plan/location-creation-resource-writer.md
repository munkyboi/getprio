# Vendor branch creation resource writer

Vendor branch POST uses the tenant catalog transaction: numeric existing-branch locks, tenant FK target and current `tenant.location.manage` grants precede creation. The server-selected tenant overwrites body scope. Active creation reads the existing billing subscription/plan location limit with exact identifiers and held policy rows; subscription-first contention returns `409 LOCATION_POLICY_BUSY` without a tenant-FK lock cycle. The existing location-limit merge/default behavior is retained. Inactive branch creation does not require quota admission.

Payload validation and platform timezone reads use the transaction client. Primary replacement, branch insertion, seven closed default-hours rows and one revision per existing/new branch commit together; hours or revision failure rolls everything back. Tenant/generated branch IDs and hour reads/writes remain exact PostgreSQL identifiers. Existing 201 response and formatting remain. No allocation, inferred occupancy or timing is created.

Real isolated PostgreSQL tests cover default timezone/hours and primary replacement, current revoked/deleted/suspended/staff denial, invalid payload/quota rejection, last-slot and duplicate creation, held branch/grant and actual quota policy contention, hours/final-revision rollback, exact adjacent large tenant quota/generated branch/hour IDs, body scope tampering, inactive/no-branch administration and preserved admitted bookings/plans/protection/allocations. Actual HTTP tests cover staff denial and authenticated owner forwarding/response.

Branch PATCH/reactivation, internal/onboarding branch creation, other settings, protection cleanup and activation reconciliation remain outside this slice. In particular, this serializes creation against creation; the legacy PATCH/reactivation limit check is not yet a covered writer. Tracking and writer coverage remain disabled and producer stays not_ready. No schema, dashboard/mobile UI, estimate, inference, capture or export changes. Live authenticated branch-form execution remains unverified.
