# Vendor availability editing writer

Weekly-rule and date-exception PATCH routes pass the authenticated actor and server-resolved tenant to an editing service. The service discovers a tenant-owned entry and any requested destination, then enters the current-authorized branch transaction. Assigned staff, revoked membership, deleted/suspended users and foreign branches are denied; inactive tenant/branch administration remains supported. Request actor, tenant and location IDs never become write authority.

The scoped transaction can lock additional branches in database ID order before domain rows. Every branch must belong to the same tenant. Accepted tenant/user/membership grants are held through commit. Additional locks do not widen the primary scope's ledger-command capability. Existing callers keep their single-branch lock behavior.

After those locks, editing locks and rereads the entry. A deleted entry returns 404; a moved entry returns 409 and requires reload. The requested destination is resolved again on the transaction client; a changed slug binding is rejected. Payload validation uses current destination hours and current tenant service selection. Retained services are also held through commit. Omitted fields use the locked current record, so concurrent partial saves preserve independent fields. Explicit All services clears the selection. Overnight, capacity, exception-date, public-text and activity semantics remain intact. Stored PostgreSQL DATE values normalize to their local calendar day for partial validation without UTC day shifts. PATCH responses retain their existing metadata shape.

The edit and one revision per affected branch commit together. Same-branch saves increment once; moves increment source and destination once each. Valid repeated saves retain ordinary editing semantics and each successful save advances once. Entry changes, scope creation and both revisions roll back together on failure, including failure after the final revision update. Opposing branch moves use the same lock order. Existing bookings, protected reservations, actual allocations and explicit service timing remain intact; moving an availability rule never moves a booking or releases occupancy.

Availability creation and deletion share payload/entry helpers without changing their transaction or response contracts. Disposable PostgreSQL tests exercise actual availability/location/service repositories and the real ledger migration with minimal application tables. Coverage includes partial/concurrent edits, opposing branch moves, tenant isolation, current grants/entry/hour/service/slug state after contention, held branch/entry/service/access locks, atomic rollback and preserved protection/occupancy. HTTP/handler tests cover staff denial, authenticated actor forwarding and metadata shapes. Authenticated live vendor form execution remains unverified.

Catalog/settings/default-hours writers, protection cleanup and activation reconciliation remain uncovered. Resource tracking and writer coverage stay disabled; the producer remains `not_ready`. No migration, dashboard/mobile UI, customer estimate, inference or capture/export changes are included.

Local validation: full isolated PostgreSQL backend coverage passed 1,128 tests with seven opt-in skips (1,135 total), zero failures. The focused PostgreSQL/handler/HTTP suite passed 172 tests before the final additional tenant-isolation case. Changed-source ESLint, backend typecheck and diff checks passed.
