# Enforced queue intake and deadline writer

Vendor pause, resume and deadline extension for enforced Queue Days now enter the location-first vendor ledger transaction before locking the Queue Day. Current `tenant.queue.operate`, active user/membership, branch assignment or active counter access for staff, active tenant/branch and enforced lifecycle mode are reread under that boundary. Accepted tenant, user, membership and assignment/counter grants remain locked through commit. Audit events use the current locked tenant role. Missing actors and identities unsafe for existing numeric Queue Day repositories reject.

The branch lock uses `FOR NO KEY UPDATE`: branch mutations still serialize, while foreign-key key-share reads can proceed. The legacy manual intake helper adopts the same compatible lock; tenant-first access changes can update a membership and insert its branch assignment while an intake request waits for the tenant. Separate Queue Day-first reconciliation can also insert branch-FK events while an enforced intake request waits for its Queue Day. Those system paths remain outside coverage certification.

Intake changes retain optimistic versions and same-mode idempotency. Deadline extension retains the reason requirement, 15-minute warning window, 30-minute increment, extension history, stale warning obsolescence, lifecycle event and durable staff notification intent. Its deadline predicate uses current database time rather than transaction-start time, so a request that waits past closing cannot extend an expired deadline. A committed transition advances the branch ledger revision atomically; a duplicate intake request or rejected action does not advance it.

An overdue intake request retains existing closure reconciliation: closure, ticket outcomes, event/outbox and one branch revision commit, then the requested intake action rejects with `QUEUE_DAY_OVERDUE`. Repeats do not add another transition/revision. Reconciliation failures roll back together. Closure retains actual allocation occupancy, explicit timing history and already-terminal linked booking statuses. This slice does not add terminal unused-protection cleanup.

Tests use real Queue Day, event/outbox and draft/ledger migrations and repositories in an isolated loopback PostgreSQL schema. They cover concurrent transitions/extensions, stale versions, current access/activity/mode, both staff assignment paths and their held grants, branch-FK access-change races, rollback after event/outbox writes, deadline expiry during a branch lock wait, overdue reconciliation and occupancy retention, and Queue Day-first reconciliation lock compatibility. Legacy manual close/reopen/pause/resume retain their paid-admission race coverage and gain tenant-first assignment regressions.

Manual enforced close/reopen are covered separately in [Enforced close/reopen](enforced-close-reopen-resource-writer.md). Manual enforced opening is covered separately in [Enforced opening](enforced-opening-resource-writer.md). Scheduled closure and Platform retries are covered separately in [Queue Day reconciliation](queue-day-reconciliation-resource-writer.md). Actor-free request reconciliation revisions, terminal protection cleanup, account deletion, related catalog/settings writers and full activation reconciliation remain inventory gaps. Tracking and writer coverage stay constrained to false, and the producer remains `not_ready`. No UI, migration, customer estimate, capture/export or inference change; authenticated live vendor flow acceptance is separate.
